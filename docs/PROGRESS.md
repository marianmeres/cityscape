## Decisions log

- **2026-06-19** — Locked the seven decisions in SPEC §1 (palette system, display-list+Canvas+ASCII, muted synth audio, passive+light interaction, engine/content subpath exports, seeded determinism, thorough tests).
- **2026-06-19** — Panel builds DOM via `createElement` + vanilla reactive core (schema-driven controls don't fit a static `<template>`); honours "no markup-from-strings" (no `innerHTML`).
- **2026-06-19** — Ambient sound modelled as a pure sim event (`AmbientEventBus`); WebAudio synth is a browser adapter, keeping the core DOM-free.
- **2026-06-19** — Adversarial review (5-dimension workflow, find→verify→confirm) returned 4 confirmed bugs, all fixed: (1) sky paint order — flyers now drawn behind clouds [skyline.ts]; (2) ASCII polygon scanline off-by-one [ascii-renderer.ts]; (3) panel `toggle(collapse)` force semantics corrected to classList-style [panel.ts]; (4) renderer disposal on teardown. For (4) I diverged from the literal "dispose on every swap" suggestion — swapping is _deactivation_ (the example reuses Canvas⇄ASCII), so disposing on swap would break reuse. Instead the handle disposes the renderer it created in `destroy()`; renderers passed to `setRenderer` are caller-owned. [mount.ts]
- **2026-06-19** — Browser-runtime bug found on first real run: the engine's first frame has a 0ms delta → 0 fixed-update steps → `collect()` ran before any `update()`, and entities draw from a mood cache seeded in `update()` → crash (`reading 'sky'`). Fix: scene primes itself in `resize()` via a `dt:0` `#tick()` (resolves mood, spawns skyline, seeds caches); structural rebuilds re-prime too. Regression test added (collect-before-update). [scene.ts]
- **2026-06-19** — Building proportions wrong on a 16:9 screen (tall, narrow towers): heights scaled with viewport height but widths were absolute px. Fix: horizontal world coordinates (widths, gaps, scroll, local x) are now in **viewport-height units**, converted to px in `Camera.project` via `unit = viewport height`; `speed` stays px/sec. Building widths derive from height by a per-archetype aspect ratio. Result: aspect ratios are constant at any window size (resize scales uniformly). Touched camera, kinds, district gaps, building draw, star/cloud wrap, and 2 tests. [camera.ts, kinds.ts, district.ts, building.ts]
- **2026-06-19** — Feature round: `zoom` (camera distance, folded into `Camera.unit`); skyscrapers excluded from the front layer (spawner `excludeKinds` + substitution); non-uniform building spacing (district touch/plaza gap rolls); per-window tint + brightness variation [window-grid.ts]; panel horizontal-scrollbar fix (`box-sizing: border-box`).
- **2026-06-19** — Waterfront: bottom `waterLevel` is a reflective `Water` plane; tightened the parallax layer ranges so even 2 bands read close together; building feet compute their baseline live from `waterLevel`.
- **2026-06-20** — Shore + vertical camera: a lit `Shore` embankment (streetlights + water reflections) separates city from water (building feet sit on it via `shoreHeight`). Vertical camera movement added as a single `DisplayList.offsetY` (camera aim + slow `verticalDrift` + pointer-Y), applied at the renderer seam; backdrop/water over-draw ±0.3h so the pan never gaps. [shore.ts, water.ts, backdrop.ts, camera.ts, world.ts, both renderers]
- **2026-06-20** — `showStats` was a dead toggle (no overlay) — implemented an FPS / entity-count / draw-count overlay in `runtime/mount.ts`, gated by `config.showStats`.
- **2026-06-20** — Docs: added `README.md` (with honest authorship note — 100% AI-authored, human-curated), `API.md`, and `AGENTS.md`; initial git commit.
- **2026-06-20** — Third renderer: `PixelArtRenderer` (`render/pixelart`), a low-res, scene-palette, ordered-dithered Canvas2D target — a third proof of the seam. Pipeline: rasterise the same `DisplayList` into an offscreen buffer (1 art-pixel = `pixelScale` CSS px, DPR-independent) → quantise to a palette extracted from the frame **as rendered** (median cut, refreshed every ~18 frames so it tracks the mood without shimmering) with **two-nearest Bayer ordered dithering** (each cube cell stores its two nearest palette colours + the mix fraction; the dither picks between them) → nearest-neighbour upscale. The hard colour math lives in pure, DOM-free, unit-tested helpers under `engine/render/pixel` (`makeBayer`, `extractPalette`, `buildPaletteLut`, `ditherQuantize`) — only the canvas glue is browser-only, mirroring `CanvasRenderer`. Extracted the per-`DrawCommand` Canvas2D switch into `render/shared/draw2d.ts` so Canvas + PixelArt share one rasteriser (no duplication; a new primitive is handled once). Added `oklab()`/`oklabDistanceSq()` to `engine/math/color.ts`. Wired a third "Pixel view" toggle into the example (`p`; `[`/`]` adjust pixel size). **Decision:** `pixelScale` is a _renderer_ option, not a `CONFIG_SCHEMA` knob — the schema is simulation state that flows into permalinks, and a pixel-size slider would be inert in the Canvas/ASCII views (unlike `vignette`, which applies to the always-on production canvas). +15 tests (`pixel-dither`, `pixel-palette`). [render/pixelart, render/shared/draw2d.ts, engine/render/pixel/*, engine/math/color.ts, example/main.ts]
- **2026-06-20** — Aesthetic call (user deferred the look): chose palette **+ ordered dithering** with a generous, mood-derived palette (~48 colours) rather than a minimal retro set — "obviously pixel-art but still pleasant". First cut used perturb-then-nearest dithering, which only mixes at cube-cell boundaries (mostly bands with a sparse palette); switched to two-nearest ordered dithering for a clean cross-hatch across the whole tone transition.
- **2026-06-20** — Adversarial review of the pixel-art work (4-dimension workflow, find→verify, 18 agents) → 8 confirmed findings (0 high, 4 medium, 4 low), all in the new renderer/example, none in the library core. Fixed: (1) example `[`/`]` keys re-sized the **shared** canvas even in Canvas mode (the pixel renderer reuses `handle.canvas`) → gated `adjustPixelScale` to pixel mode [example/main.ts]; (3) `setOptions` reallocated the buffer + forced a palette+LUT rebuild on _any_ option change → now resizes only when `pixelScale` actually changes [pixelart-renderer.ts]; (6) `imageSmoothingEnabled=false` leaked on the shared 2D context → restored to default after the upscale blit [pixelart-renderer.ts]; (5) shared the alpha-skip threshold between `extractPalette`/`ditherQuantize` via a named const [palette.ts]; (7) fixed a stale pre-existing `randomizeSeed` comment [example/main.ts]. Documented (not "fixed", they're inherent): (2) per-frame `getImageData` readback/allocation cost scales with buffer area → cost note on `pixelScale` [pixelart-renderer.ts, API.md]; (4) the throttled median-cut palette can _step_ on a fast mood change → tempered the "without shimmering" claim to "without per-frame shimmer" [pixelart-renderer.ts]. Declined (8): sub-art-pixel edge "boil" along moving silhouettes is inherent to rasterise-then-quantise; the screen-anchored Bayer keeps it stable, and snapping edges to the art grid would kill smooth parallax. `willReadFrequently:true` on the offscreen context (user-reported console warning).
